# STATEFLUX — Controlled Real IPsec Lab

## Purpose
The STATEFLUX Controlled Lab provides a deterministic local testbed using **strongSwan 5.9.8** and **Libreswan 4.12** in isolated Linux network namespaces / Docker containers.

Its sole purpose is **Prediction Validation**:
Validating whether the cryptographic negotiation and rekey predictions generated by the STATEFLUX What-If Simulation Engine match actual IPsec daemon behaviors.

## Controlled Scenarios

| Scenario ID | Name | Platforms | Expected Outcome |
| :--- | :--- | :--- | :--- |
| **LAB-01** | Secure Suite-B Baseline | strongSwan <-> strongSwan | **ESTABLISHED** (AES-256-GCM / Group 20) |
| **LAB-02** | Weak Functional Fallback | strongSwan <-> strongSwan | **ESTABLISHED** (AES-128-CBC / Group 14, warning logged) |
| **LAB-03** | Encryption Incompatibility | strongSwan <-> Libreswan | **FAILED** (`NO_PROPOSAL_CHOSEN`) |
| **LAB-04** | DH Group Incompatibility | strongSwan <-> strongSwan | **FAILED** (`NO_PROPOSAL_CHOSEN`) |
| **LAB-05** | Latent Rekey Failure | strongSwan <-> Libreswan | **LATENT_FAILURE** (Initial SA UP, rekey negotiation FAILS) |

## Running the Lab in Docker
When Docker is installed and running on a Linux or Docker Desktop host:
```bash
# Build and run scenario 1
docker compose up -d
docker compose exec gateway-a swanctl --initiate --child net-net
docker compose exec gateway-a swanctl --list-sas

# Or execute via the test script
./lab/scripts/run_lab.sh LAB-01
```

When running within the automated STATEFLUX test harness or API service, the `LabService` executes the scenarios and generates validated `LabResult` artifacts with complete Charon / Pluto daemon logs.
